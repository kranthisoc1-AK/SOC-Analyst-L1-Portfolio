# Module 9: Network Attack Detection

## 1. Project Overview

**Objective:** Perform basic network monitoring and investigation using Windows PowerShell, Windows Event Viewer and Wireshark.

**Environment:**
- Operating System: Windows 11
- Hostname: DESKTOP-L29HLL9
- SIEM: Wazuh
- Network Analysis Tool: Wireshark
- Additional Tools: Windows PowerShell, DNS Client logs

## 2. Network Configuration

Identified the active Wi-Fi network interface.

- Local IPv4 address: 192.168.1.36
- Default Gateway: 192.168.1.1
- DNS Servers: 110.235.231.81 and 144.48.72.72

Also identified virtual network interfaces associated with Docker, Hyper-V and WSL.

## 3. TCP Connection Investigation

Used Get-NetTCPConnection to inspect established connections.

Observed:
- 82 established TCP connections in an initial snapshot.
- HTTPS connections using remote port 443.
- Localhost connections associated with local applications and services.

Identified application processes behind selected network connections.

## 4. DNS Investigation

Inspected the Windows DNS cache using ipconfig /displaydns.

Enabled the DNS Client Operational event log and verified that logging was active.

Generated a DNS lookup using:

nslookup microsoft.com

Observed successful DNS resolution.

Investigated DNS Client events:
- Event ID 3008: DNS query completed.
- Event ID 3010: DNS query sent.
- Event ID 3011: DNS server response received.
- Event IDs 3016, 3018, 3019 and 3020: Additional DNS query and cache activity.

Identified OneDrive.Sync.Service.exe as the process associated with a Microsoft telemetry DNS query.

Checked its Authenticode signature and observed Status: Valid.

## 5. UDP Investigation

Used Get-NetUDPEndpoint to inspect UDP endpoints.

Observed 51 UDP endpoints in one snapshot.

Reviewed common ports:
- 53: DNS
- 67/68: DHCP
- 123: NTP
- 137/138: NetBIOS
- 1900: SSDP
- 5353: mDNS
- 5355: LLMNR

Identified associated processes, including Chrome, Docker Desktop and Windows services.

## 6. Windows Service Investigation

Identified the following services:

| Service | Purpose |
|---|---|
| Dnscache | DNS Client |
| IKEEXT | IPsec key management |
| SharedAccess | Internet Connection Sharing |
| SSDPSRV | SSDP Discovery |
| W32Time | Windows Time |

All five services were running during the investigation.

## 7. Wireshark Packet Analysis

Used Wireshark to capture live network traffic.

Performed packet filtering using:
- dns – DNS traffic
- tcp – TCP traffic
- udp – UDP traffic

Generated a DNS query for google.com and verified that its DNS query and response appeared in Wireshark.

## 8. TCP Connection State Investigation

Observed the following TCP connection-state counts in a later snapshot:

| State | Count |
|---|---:|
| Listen | 51 |
| Bound | 46 |
| Established | 69 |
| TimeWait | 12 |
| CloseWait | 2 |
| FinWait2 | 1 |

These values represent a point-in-time observation, not proof of an attack.

## 9. Listening Port Investigation

Inspected listening TCP ports and identified associated processes.

Examples:
- WSL Relay
- Docker Backend
- Splunkd
- MongoDB
- OneDrive Sync Service
- Windows system services

Observed ports included 135, 139, 443, 445, 1514, 1515, 8089 and 9200.

The identified processes were consistent with the Windows, Docker, WSL and Splunk lab environment. No confirmed malicious listening process was identified.

## 10. SOC Analyst Findings

The investigation demonstrated how to:

1. Establish a basic network baseline.
2. Inspect established TCP connections.
3. Investigate DNS cache records.
4. Analyze Windows DNS Client events.
5. Identify processes responsible for network activity.
6. Verify executable digital signatures.
7. Inspect UDP endpoints.
8. Identify Windows services.
9. Capture and filter network packets using Wireshark.
10. Review listening ports and associated applications.

**Investigation conclusion:** No confirmed malicious network activity was established from the observations collected. The results represent a limited baseline investigation, not a guarantee that the system is free of threats.

## 11. Limitations and Pending Validation

- No controlled port-scan simulation was performed.
- No confirmed DNS tunneling or network attack was identified.
- Wazuh network alert correlation was not validated as part of this module.
- The observed connection and endpoint counts are snapshots and can change over time.

## 12. Conclusion

This project provided practical experience in Windows network monitoring, DNS investigation, TCP/UDP analysis, Wireshark packet inspection and process identification.

These activities are relevant to SOC Analyst Level 1 responsibilities, particularly initial network investigation and identifying potentially suspicious communication.
