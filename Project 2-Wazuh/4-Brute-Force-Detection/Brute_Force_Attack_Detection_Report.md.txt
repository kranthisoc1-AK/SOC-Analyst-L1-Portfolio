# PROJECT REPORT
# Windows Brute Force Attack Detection Using Wazuh SIEM

## 1. Project Overview

This project demonstrates the detection and monitoring of Windows brute-force login attempts using Wazuh SIEM.

A brute-force attack is a type of cyberattack in which an attacker repeatedly attempts to guess a user's password to gain unauthorized access to a system.

In this project, multiple failed login attempts were simulated on a Windows 11 endpoint. Windows Security Event ID 4625 was used to identify failed login attempts. These security events were collected and monitored through the Wazuh SIEM platform.

A monitoring dashboard was also created to visualize failed login activity and support security investigation.

## 2. Project Objectives

The main objectives of this project are:

- Understand how brute-force attacks work.
- Simulate multiple failed login attempts on a Windows endpoint.
- Monitor Windows Security Event ID 4625.
- Collect and analyze security events using Wazuh SIEM.
- Create visualizations to monitor failed login activity.
- Investigate suspicious authentication attempts.
- Understand how SOC analysts identify potential brute-force attacks.

## 5. Attack Simulation

To simulate brute-force activity, a local Windows test account named `SOC-LabUser` was used.

The following steps were performed:

1. Created a test Windows user account.
2. Configured Windows auditing for logon events.
3. Generated multiple failed login attempts using an incorrect password.
4. Checked Windows Event Viewer for failed authentication events.
5. Identified Event ID 4625.
6. Verified that multiple failed login events were collected in Wazuh.

**Important Event ID:**

- 4625 – An account failed to log on.

These events helped identify repeated authentication failures against the Windows endpoint.

## 6. Wazuh Alert Analysis

The Windows endpoint generated failed login events, which were monitored using Wazuh Threat Hunting.

The following fields were examined during investigation:

| Field | Purpose |
|---|---|
| `agent.name` | Identifies the affected endpoint |
| `agent.id` | Identifies the Wazuh agent |
| `data.win.system.eventID` | Identifies the Windows event |
| `data.win.eventdata.targetUserName` | Identifies the targeted username |
| `data.win.eventdata.ipAddress` | Identifies the source IP address, when available |
| `rule.id` | Identifies the Wazuh detection rule |
| `@timestamp` | Shows when the event occurred |

The following query was used in Wazuh Threat Hunting:

```text
agent.id: "002" AND data.win.system.eventID: "4625"
```

This query helped identify failed login events generated by the Windows endpoint.

## 7. Dashboard and Visualizations

A custom monitoring dashboard was created with the following visualizations.

**Dashboard Name:**

SOC - Brute Force Attack Monitoring

### Visualization 1: Windows Failed Login Attempts

- Visualization Type: Line Chart
- Index Pattern: `wazuh-alerts-*`
- Filter: Event ID 4625
- X-axis: Date Histogram using `@timestamp`
- Metric: Count

Purpose: Displays failed login activity over time.

### Visualization 2: Total Failed Login Attempts

- Visualization Type: Metric
- Metric: Count
- Filter: Event ID 4625

Purpose: Displays the total number of failed login events in the selected time range.

### Visualization 3: Top Targeted User

- Visualization Type: Data Table
- Aggregation: Terms
- Field: `data.win.eventdata.targetUserName`
- Metric: Count

Purpose: Identifies usernames receiving the highest number of failed login attempts.

### Visualization 4: Top Source IP Addresses

- Visualization Type: Data Table
- Aggregation: Terms
- Field: `data.win.eventdata.ipAddress`
- Metric: Count

Purpose: Helps identify source IP addresses associated with failed authentication attempts.

## 8. Investigation Findings

During the investigation, the following activities were performed:

1. Multiple failed login attempts were generated against the test Windows account.
2. Windows Security Event ID 4625 was identified.
3. Failed login events were successfully observed in Wazuh Threat Hunting.
4. Existing Wazuh rule ID 60122 was identified in the event details.
5. A Wazuh monitoring dashboard was created.
6. Visualizations were configured to display failed login trends, total failures, targeted usernames and source IP addresses.

**Security Assessment:**

Repeated failed login attempts may indicate password guessing or brute-force activity. However, failed logins alone do not prove that an attacker successfully accessed the system. Further investigation of successful logins, source IP addresses, account activity and timestamps is necessary.

## 9. Conclusion

This project provided practical experience in detecting and monitoring suspicious authentication activity using Wazuh SIEM.

The project demonstrated how Windows Security Event ID 4625 can be used to identify failed login attempts and how Wazuh can collect and visualize these events.

The monitoring dashboard provided a foundation for analyzing repeated failed login activity.

Through this project, practical knowledge was gained in Windows log monitoring, SIEM configuration, security event analysis, dashboard creation and SOC investigation workflows.

These skills are relevant to the responsibilities of a Security Operations Center (SOC) Analyst Level 1.
