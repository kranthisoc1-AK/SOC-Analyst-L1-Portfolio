# 1. Project Objective

The objective of this project was to understand and investigate common Windows persistence techniques using PowerShell, Windows Event Logs, and Wazuh.

Persistence is a technique used by attackers to maintain access to a compromised system even after a system restart or user logout.

This investigation focused on identifying suspicious startup entries, scheduled tasks, Windows services, registry autorun entries, and startup folder modifications.

# 3. Scheduled Task Persistence Detection

## Objective
To identify scheduled tasks that could be abused by attackers to execute malicious programs automatically.

## Investigation

Listed scheduled tasks using PowerShell:

```powershell
Get-ScheduledTask |
Select-Object TaskName, TaskPath, State |
Format-Table -AutoSize
```

Filtered ready scheduled tasks:

```powershell
Get-ScheduledTask |
Where-Object {$_.State -eq "Ready"} |
Select-Object -First 20 TaskName, TaskPath, State |
Format-Table -AutoSize
```

The system contained approximately 275 scheduled tasks.

## Windows Event Logging

Checked Task Scheduler Operational logging:

```powershell
wevtutil get-log Microsoft-Windows-TaskScheduler/Operational /format:xml
```

The channel was initially disabled.

Enabled the channel:

```powershell
wevtutil set-log Microsoft-Windows-TaskScheduler/Operational /enabled:true
```

Created a harmless test scheduled task:

```powershell
schtasks /create /tn "SOC_Persistence_Lab" /tr "cmd.exe /c exit 0" /sc ONCE /st 23:59 /f
```

A second test task was also created:

```powershell
schtasks /create /tn "SOC_Persistence_Test2" /tr "cmd.exe /c exit 0" /sc ONCE /st 23:59 /f
```

Verified the task registration event:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Microsoft-Windows-TaskScheduler/Operational'
    Id = 106
} -MaxEvents 10 |
Select-Object TimeCreated, Id, Message |
Format-List
```

## Observation

Windows generated Event ID 106, confirming that the test scheduled task was registered.

The event message identified the registering account and task name.

The Wazuh agent configuration was updated to collect the Task Scheduler Operational channel:

```xml
<localfile>
  <location>Microsoft-Windows-TaskScheduler/Operational</location>
  <log_format>eventchannel</log_format>
</localfile>
```

The Wazuh agent was restarted to apply the configuration.

**Result:** Scheduled task registration was successfully verified in Windows Event Logs. Matching test events were not confirmed in Wazuh Dashboard.

# 4. Windows Service Persistence Detection

## Objective
To investigate newly installed Windows services that could be used for persistence.

Windows Event ID 7045 records the installation of a new service.

## Investigation

Executed:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'System'
    Id = 7045
} -MaxEvents 10 |
Format-List TimeCreated, Id, Message
```

Reviewed service installation events.

Observed service installations including:

- Wazuh Agent
- Google Updater
- Xbox Input Service
- Gaming Services
- GameInput Redist Service
- KslD

## Investigation of KslD

Investigated the KslD driver:

```powershell
Get-CimInstance Win32_SystemDriver |
Where-Object {$_.Name -eq "KslD"} |
Format-List Name, DisplayName, State, StartMode, PathName
```

Observed:

| Attribute | Value |
|---|---|
| Name | KslD |
| Display Name | KslD |
| State | Running |
| Start Mode | Manual |
| Path | C:\WINDOWS\system32\drivers\wd\KslD.sys |

Checked its digital signature:

```powershell
Get-AuthenticodeSignature "C:\Windows\System32\drivers\wd\KslD.sys" |
Format-List Status, StatusMessage, SignerCertificate
```

The signature status was reported as valid.

## Observation

The driver was located in a Windows Defender-related directory and had a valid digital signature.

Based on the available evidence, it appeared consistent with a legitimate system component. No malicious activity was established.

**Result:** Service installation events were reviewed, and a driver was investigated using its path and digital signature.

# 5. Registry Run Persistence Detection

## Objective
To identify programs configured to execute automatically when Windows starts or a user logs in.

Attackers may use registry autorun locations to maintain persistence.

## HKLM Run Investigation

Executed:

```powershell
Get-ItemProperty "HKLM:\Software\Microsoft\Windows\CurrentVersion\Run"
```

Observed entries:

| Registry Value | Executable |
|---|---|
| SecurityHealth | SecurityHealthSystray.exe |
| RtkAudUService | RtkAudUService64.exe |

These entries appeared consistent with Windows Security and Realtek software based on their names and paths.

## HKCU Run Investigation

Executed:

```powershell
Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run"
```

Observed entries:

| Registry Value | Executable |
|---|---|
| OneDrive | OneDrive.exe |
| Docker Desktop | Docker Desktop.exe |
| MicrosoftEdgeAutoLaunch | msedge.exe |

The entries appeared consistent with installed applications.

## RunOnce Investigation

The following locations were selected for inspection:

```powershell
Get-ItemProperty "HKLM:\Software\Microsoft\Windows\CurrentVersion\RunOnce"
```

```powershell
Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\RunOnce"
```

The results of these checks were not captured in the investigation evidence.

**Result:** HKLM Run and HKCU Run entries were reviewed. RunOnce findings remain undocumented.

# 6. Windows Startup Folder Investigation

## Objective
To identify programs configured to launch automatically through Windows Startup folders.

## Current User Startup Folder

Executed:

```powershell
Get-ChildItem "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup" -Force
```

Observed:

- desktop.ini

No additional startup shortcuts or executables were displayed.

## All Users Startup Folder

The intended inspection command was:

```powershell
Get-ChildItem "C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup" -Force
```

The output from this specific path was not captured.

**Result:** The current user's Startup folder was inspected. The All Users Startup folder requires separate confirmation.

# 7. Automatic Windows Service Analysis

## Objective
To review services configured to start automatically with Windows and identify unfamiliar services or executable paths.

Executed:

```powershell
Get-CimInstance Win32_Service |
Where-Object {$_.StartMode -eq "Auto"} |
Select-Object Name, DisplayName, State, StartMode, PathName |
Format-Table -AutoSize
```

Reviewed services including:

- Windows Defender
- Wazuh Agent
- Splunkd
- Sysmon64
- Microsoft Edge Update
- Google Updater
- Intel services
- Realtek services
- Windows system services
- WSL Service
- Hyper-V Virtual Machine Management

## Observation

The displayed service list contained several recognizable Windows, security, hardware, and installed application services.

No clearly malicious service was established from the available output.

Unfamiliar services should be investigated further by checking their executable paths, digital signatures, service accounts, and creation timestamps.

**Result:** Automatic services were reviewed as part of the persistence investigation.

# 11. Security Recommendations

1. Monitor Windows Event ID 106 for scheduled task registration.
2. Investigate unfamiliar scheduled tasks and their execution commands.
3. Monitor Windows Event ID 7045 for new service installations.
4. Verify executable paths and digital signatures of unfamiliar services.
5. Monitor registry autorun locations, including Run and RunOnce.
6. Monitor Windows Startup folders for unexpected executables and shortcuts.
7. Configure Wazuh FIM to monitor important registry keys and startup directories.
8. Investigate unexpected PowerShell, command prompt, and script execution.
9. Correlate Windows events with endpoint activity and timestamps.
10. Validate that expected events are actually received and indexed by Wazuh.

The investigation covered scheduled task registration, Windows service installation events, registry autorun locations, Startup folders, automatic services, and Wazuh agent monitoring.
