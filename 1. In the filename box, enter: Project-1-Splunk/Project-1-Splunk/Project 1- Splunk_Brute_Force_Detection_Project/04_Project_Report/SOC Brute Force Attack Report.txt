* Project Report
* Splunk-Based Brute-Force Attack Detection and Investigation

1. Project Overview

This project demonstrates how Splunk Enterprise can be used as a Security Information and Event Management (SIEM) tool to monitor Windows Security Logs, detect suspicious login attempts, generate alerts, and support security investigations.

2. Project Objective

- Monitor Windows Security Events using Splunk.
- Identify repeated failed login attempts.
- Detect possible brute-force attacks.
- Configure automated alerts for suspicious login activity.
- Investigate failed and successful login events.
- Create a dashboard to visualize login activities.

3. Tools and Technologies Used

- Splunk Enterprise
- Windows 11
- Windows Security Event Logs
- Search Processing Language (SPL)

4. Lab Environment

- Operating System: Windows 11
- SIEM Platform: Splunk Enterprise
- Log Source: Windows Security Event Log
- Test Account: SOC-LabUser
- Event ID 4625: Failed Logon
- Event ID 4624: Successful Logon

### 5. Log Collection and Configuration
Configured Splunk Enterprise to monitor Windows Security Event Logs.

Collected authentication-related security events, including:
- Event ID 4624 – Successful logon.
- Event ID 4625 – Failed logon.

### 6. Brute-Force Attack Simulation
Created a standard Windows test account named SOC-LabUser.

Generated multiple failed login attempts by entering an incorrect password five times within a five-minute period.

These events were recorded in Windows Security Logs and collected by Splunk.

### 7. Detection Logic
Used SPL to identify five or more failed login attempts within a five-minute interval.

Example query:

```spl
sourcetype="WinEventLog:Security" EventCode=4625
| bin _time span=5m
| stats count as Failed_Attempts by host _time
| where Failed_Attempts >= 5
```

8. Alert Configuration

Created a scheduled alert named "Brute Force Attack Alert".

Configuration:
- Alert Type: Scheduled
- Cron Schedule: */5 * * * *
- Trigger Condition: Number of Results greater than 0
- Severity: High
- Trigger Action: Add to Triggered Alerts

The alert identifies suspicious failed login activity matching the detection condition.

9. Dashboard Development

Created a Splunk dashboard named "Brute Force Attack Detection Dashboard".

The dashboard includes relevant visualizations and investigation panels for:
- Failed Login Detection
- Failed Login Activity Over Time
- Successful vs Failed Logins
- Failed Login Investigation Details
- Failed Login Investigation Summary

10. Security Investigation

Investigated the detected login activity by reviewing:
- Failed login timestamps.
- Windows computer/host information.
- Event ID 4625.
- Affected test account, where available.
- Successful login activity following failed attempts.

11. Findings

The lab successfully generated five failed Windows login attempts and Splunk detected the activity using the configured detection search.

A High-severity alert was configured to identify matching activity.

12. Recommended SOC Analyst Response

1. Identify the affected user account.
2. Investigate the source IP address when available.
3. Review successful login events after the failed attempts.
4. Determine whether the activity is legitimate or suspicious.
5. Escalate confirmed suspicious activity to the SOC L2 team.
6. Document the investigation findings.

13. Conclusion

This project provided practical experience with SIEM monitoring, Windows Security Log analysis, SPL queries, brute-force detection, alert configuration, dashboard creation, and incident investigation.

It demonstrates fundamental SOC Analyst Level 1 skills in security monitoring and alert investigation.
